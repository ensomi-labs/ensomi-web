R2 · 誰でも遊べる最初のリリース

ensomi — Play the music around you.

えんそみ — 聴く音楽から、参加する音楽へ。

好きな曲を選ぶと、R2 がこのブラウザの中で譜面を作ります。音楽に合わせて譜面が流れるのを見てから、osu! に取り込んで自分で遊んでみてください。曲がパソコンの外に送られることはありません。

譜面の生成にはパソコンのブラウザが必要です。モデルを読み込み、曲を選んで譜面を生成するには、このページをパソコンで開いてください。

譜面を生成

1モデル

モデルの取得元

初回は sed-i/ensomi-r2 から約 120 MB をダウンロードし、2 回目以降はこのブラウザのキャッシュから読み込みます。ブラウザが対応していればビート検出に WebGPU を使い、それ以外は WebAssembly のスレッドで処理します。モデルがキャッシュ済みの状態で、3 分 20 秒の曲が Apple M5 の Chrome で約 6 秒、WebGPU なしで約 13 秒でした。

2曲

このブラウザでデコードできる形式なら何でも使えます。ファイルはパソコンの外に送られません。

3条件

生成された譜面は、指定した★より易しくも難しくもなることがあります。難易度のコントロールは今後改善していきます。

曲を元のサンプルレートでデコードし、Python 版と同じ方法で変換します。ビートの時刻が Python 版と数千分の 1 ミリ秒以内で一致します（オフのときは最大約 1.3 ms ずれます）。1 曲あたり約 0.5 秒余分にかかり、サンプルレートの高いファイルではさらにかかります（96 kHz で約 1.3 秒）。

区間 任意

曲の一部の範囲に、スタイルや目標の★を指定できます。時刻は mm:ss で入力します。各区間は 8〜32 秒で、曲の範囲内に収め、ほかの区間と重ねないでください。ある区間の終わりから次の区間を始めることはできます。

  1. 準備
  2. タイミング
  3. ノーツの位置
  4. 配置
  5. 書き出し

モデルを読み込んで曲を選ぶと、生成を始められます。

ensomi をつくる理由

音楽はたいてい、聴くものです。リズムゲームなら、曲の中に入り込めます。手がビートを追いかけ、聴くことが遊ぶことに変わります。けれど、曲が遊べるようになるのは、誰かが一つひとつ手で譜面を作ってから。身の回りの音楽のほとんどには、譜面がありません。

それを変えたいと考えています。ensomi はマッパーが作った譜面から学び、音声から新しい譜面を書きます。好きな音楽も、すでに身の回りに流れている音楽も、遊べるものにするために。

私たちがつくっているもの

音楽を聴くこと、遊ぶこと、譜面を作ること。それらをひとつの体験にしたいと考えています。四つの場面で、その意味をお見せします。

まわりの音楽で遊ぶ

身の回りの音楽が、遊べるものになる。

近くで曲がすでに流れています。ensomi はその曲を認識して再生位置を見つけ、リアルタイムで生成した譜面を始めます。譜面は音楽を止めることなく、音楽についていきます。

譜面制作

配置を決めるのはあなた。ensomi は候補を出します。

マッパーが一つのパッセージを選び、配置の候補を求めます。譜面のほかの部分はそのままです。候補を見比べて、残す、やり直す、元に戻す。選択も表現も、マッパーのものです。

練習

好きな音楽で練習する。

プレイヤーが好きな曲と上達したい動きを選ぶと、その動きを軸に譜面ができあがります。

一緒に遊ぶ

あなたのいいプレイが、相手の譜面に降ってくる。

対戦テトリスでラインを消すように、きれいに叩けたパッセージや長いコンボが攻撃になります。ノーツの連打や難しいパターンが、相手がこれから叩く譜面に落ちてきます。協力プレイでは息を合わせ、一人のプレイがもう一人の譜面を形づくります。

まだそこまでは来ていません。どの場面にも、指定した難易度で遊べて、音楽に沿い、曲全体でひとつのキャラクターを保ち、頼んだことに応える譜面が必要です。R2 はその最初の一歩です。待っている間に曲全体の譜面ができ、曲の一部にスタイルを指定することもすでにできます。ただし、音楽とリアルタイムで一緒に流れる譜面、プレイ中に変わる譜面、既存の譜面の一部の作り直しには、まだ対応していません。

R2：曲から、遊べる譜面へ

R2 は、誰でも遊べる私たちの最初のリリースです。音声だけをもとに動き、曲が譜面になるまでに三つのことが起きます。

  1. ビートを見つける。R2 はビートを聴き取り、テンポの区間ごとに、曲の音が鳴り始める位置へ合わせます。
  2. ノーツの位置を決める。聴こえた音をもとに、一拍ごとにノーツの始まる位置を決めます。
  3. 譜面を配置する。ノーツの置かれ方が似ている人間の譜面から、ロングノーツや同時押しの多さといったキャラクターを受け取り、レーン・通常ノーツ・ロングノーツを配置します。この段階ではまだ音声を聴いていません。

できあがるのは、ブラウザの中で作られた完全な osu!mania 4K 譜面です。音楽に合わせて流れを確認でき、そのまま osu! で開けます。

R2 と行モデルは、osu! の Ranked と Loved の 4K 譜面（★2〜6）で学習しました。それらの譜面や音声は配布していません。

次は R3

R2 は誰でも遊べる最初のリリースであり、ここからが始まりです。

いま、次のシステム R3 を開発しています。R2 と同じく、タイミング、ヘッド行（ノーツの置かれる位置）、配置（ノーツの並べ方）のすべてを扱います。R2 から学んだことに、次の順で取り組みます。

  1. 音に乗るノーツ

    ノーツは、聴こえる音の上に置かれるべきです。実際の音声により正確に合うヘッド行に取り組んでいます。

  2. 音を聴く配置

    R2 の配置は音声を聴いていません。音ではなくノーツの位置をもとにノーツを並べるため、それが音楽に沿わないロングノーツとして表れます。R3 では配置モデルに音楽の情報を取り入れ、配置も音を聴くようにします。

  3. 見えない補正を減らす

    R2 には、書いている途中で譜面を安定させるいくつかの補正ルールがあります。たとえば、与えられたキャラクターへ譜面を引き戻す復元力です。それらが特定の譜面をゆがめていないか、見直しています。

  4. 信頼できる難易度

    ★を指定したら、譜面はそれに合っているべきです。いまは指定より易しく、あるいは難しくなることがあります。難易度のコントロールを改善しており、それを正しくするには、システムの多くを作り直すことになるかもしれません。

これらは目標であり、作業は進行中です。R2 と同じく、R3 にできることは、確かめてから初めてお伝えします。

自分で動かす

上の生成器は @ensomi/runtime を使って R2 をブラウザで動かしています。ニューラルネットワークは ONNX Runtime Web で、それ以外は WebAssembly にコンパイルした ensomi の Rust ランタイムで動きます。曲のデコードと乱数はブラウザ側で行うため、ここでのシードとコマンドラインでの同じシードからは、同じ譜面にはなりません。

コマンドラインでリリース版を動かすには（Apple シリコン搭載の macOS で確認済み。Linux と CUDA では実行していません）：

git clone https://github.com/ensomi-labs/ensomi-model.git
cd ensomi-model
git checkout --detach r2-1.0.1
uv sync --python 3.10 --extra mps
hf download sed-i/ensomi-r2 --revision r2-1.0.1 --local-dir artifacts/hf-r2

uv run --python 3.10 --extra mps python -m ensomi_model.system.make \
  --model-dir artifacts/hf-r2 --audio /path/to/song.mp3 --star 3.5 \
  --title "Song title" --artist "Artist" --seed 0 --out artifacts/my-chart.osz

初回の実行では、BeatThis のチェックポイント（81 MB）も作者の配布元からダウンロードします。WAV 以外の音声のデコードには ffmpeg が必要です。--help で指定できる項目がすべて表示されます。詳しい手順は Hugging Face のモデルカード（英語）にあります。
